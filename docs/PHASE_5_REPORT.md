# v0.5.0 — Companions, paid hints and online arena beta

## What changed
- Opening landing screen with original code-drawn companions and a compact profile/gem bar. Solo, family, friends, online and ranking entry points. No copied game artwork, ads or paid assets.
- Upward winding island journey with raised puzzle nodes and three story chapters. Maze companions change from Milo (Whisper Woods) to Piku (Cloudpeak Quest) to Nila (Moonwater Falls). Number Trail has Lumi and a separate lavender/aurora palette.
- Gameplay header shows player name and persistent gem balance. Each hint costs 5 gems with an atomic local balance check. Insufficient balances disable hints. Existing progress/wallets remain intact. Replays/family/online cannot farm first-clear gems. Maze's pre-marked route crystals have been removed visually; the maze remains a unique-path tree, so the hidden route metadata does not add another user objective.
- Audio waits for loading/mode initialization, routes to speakers, pauses in background, and has louder original ambient/victory audio plus move/tap/hint/bump/next-level earcons. Movement sound throttles to 85ms. Web uses a separate media lifecycle with handled playback promises. Settings include music/effects toggles and Test sound. Native phone audibility/headphone interruptions still need acceptance.
- Friends show explicit Received, Sent and My friends sections, empty states, Accept/Decline/Cancel/Remove, paged lists, invitations and heartbeat-based online/offline status. Presence expires after 35 seconds; it is approximate, not an instantaneous transport connection guarantee.
- Public matchmaking pairs only real authenticated players waiting for the same game. Friends can invite/accept. Both get the same server-selected index/seed, 4-second start window and 3-minute deadline. No bots. No ranked hints. Match cancellation and expired queues are explicit.
- Public rankings return top 50 plus the requesting player's actual row when below 50. Within top 50 the self row occurs once. Friends rankings load all pages (200 at a time), including self, with no 50-friend cap. Rankings are all-time verified online wins; offline gems/solves do not fabricate public results.
- Match participants can send 1–160 character text messages (6 per 10 seconds, 200 per match, sending closes after 24 hours). Post-match friend request uses the actual opponent handle. Chat is per-match, not a global chat room or a persistent direct-message inbox.

## Authentication: implemented, external activation still required
Google OAuth PKCE via the system auth browser, protected native token storage and `dangal://auth/callback` are implemented. Email/password sign-in and create-account have separate clear forms and actionable errors. Cloud connection no longer depends on fetching GitHub configuration at login: public project config ships in the app. No server key ships in the client.

Live project settings currently report Google disabled, email enabled and email confirmation required. The user said no known Google OAuth client exists. Google Cloud Web OAuth client + Supabase provider/redirect settings must be configured with the owner's account before Google sign-in can work. Public email verification also still needs custom SMTP. Verification was not disabled, no fake login was added, and no test email or real account was created. See OAUTH_SETUP.md. Real two-phone Google/session acceptance is blocked by this setup, not claimed passed.

## Deployed backend
Dedicated project `qwpkqfnxbghwjztnytqh` remains healthy. Additive `social_arena` and `arena_pairing_guard` migrations deployed. New tables are RLS-enabled and deny client table access; RPCs check identity/participants. Pairing/acceptance serialize to avoid placing a participant in two active games.

`dangal-finish` TypeScript Edge Function is deployed. It authenticates the bearer token with Supabase getUser, regenerates the exact puzzle and validates the full path. Only its server-side service client can call the result writer. Result timing comes from database time; no client score/time is accepted. Function gateway JWT verification is off because the function performs authentication itself, supporting modern publishable keys. Unauthenticated HTTP submission returns 401. No service key was read, logged or copied to this repository. Engine source mirrors the mobile pure engine; keep both synchronized when changing puzzle generation.

Results/rank updates are row-locked and idempotent. This validates solved paths and server time, not resistance to bots or modified clients. All online features use Supabase RPC and its TypeScript validator; no extra paid Node/Pusher hosting was provisioned. Usage remains subject to the account's free quotas. This is a private testing beta, not a claim of production readiness.
